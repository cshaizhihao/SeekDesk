# Standard Flutter macOS runner

This is the production Flutter application's normal Xcode runner, generated by
Flutter 3.50.0. It embeds Flutter through the official generated Swift package,
with Impeller enabled and a native `FlutterHostDelegate` application entry point.

Default development builds use `com.seekdesk.flutter-preview`, with separate
defaults, website data and `com.seekdesk.flutter-preview.*` Keychain service
names. They do not automatically migrate the installed client's data.
The explicitly authorized local delivery uses `com.seekdesk.client` and the
original service names. The current `/Applications/SeekDesk.app` is this local
Flutter delivery, at the unchanged version 1.0.0 (70); it is not a new published
release. Select the intended build path rather than exchanging the two bundles.

## Build locally

Install and select full Xcode, then use the persisted Flutter 3.50 SDK:

```sh
bash scripts/build-macos.sh debug
```

Use `profile` or `release` for optimized builds. The script builds, verifies code
signatures and checks the packaged Info.plist. It does not install, launch, upload,
or publish the app. The default identity is ad-hoc for local development.

The repository's ignored `.tools` directory contains the SDK, package cache and
Flutter configuration. Every Flutter command should use the shared wrapper:

```sh
bash scripts/flutter.sh --version
bash scripts/flutter.sh analyze
SEEKDESK_PUB_OFFLINE=1 bash scripts/build-macos.sh debug
```

Set `SEEKDESK_FLUTTER_SDK=/absolute/path/to/flutter-sdk` to override the local SDK.
The previous `/tmp/seekdesk-flutter-sdk`, `/tmp/seekdesk-dart-pub-cache` and
`/tmp/seekdesk-flutter-config` paths remain compatibility symlinks on this Mac.
Full Xcode 27.2 and its official Metal Toolchain component are installed and
selected; `xcodebuild -version` and `xcrun metal -v` verify them. The original
Swift build remains available independently.

## Existing native services

The Xcode Runner target includes the existing `../../Sources/SeekDesk` Swift files
and `Runner/NativeBridge` through filesystem-synchronized groups. New Swift files
in either directory join the same `Runner` module automatically. The compilation
condition `SEEKDESK_FLUTTER` excludes the original SwiftUI `@main` application
while retaining shared native business types. The Dart-facing bridge lives in
`Runner/NativeBridge`.

Yams and CYaml are products of the repository's local `../../Vendor/Yams` package.
Sparkle 2.10.1 is linked and embedded as a framework. `prepare-native.sh` first uses
the local Sparkle xcframework when present; otherwise it downloads the pinned
official release archive and verifies the same SHA-256 as the original package
manifest. The prepared framework is ignored by Git.

The native resource phase copies the existing icons, logos, friend-link assets,
licenses and the pinned Xray helper into the expected bundle locations. Xray's
SHA-256 is checked before copying. This preview keeps the original desktop
client's non-App-Sandbox distribution model so the existing proxy helper can
run. Debug alone receives a JIT entitlement for Flutter's development VM.

The initial shipping architecture remains Apple Silicon (`arm64`), matching the
bundled Xray core. The local Flutter configuration enables macOS arm64-only
assembly so Flutter's AOT framework also avoids an unused Intel slice. The
original app version files are not changed by this runner.

## Explicit local delivery

After interactive acceptance, `bash scripts/build-local-macos.sh` prepares the
repository's `dist/SeekDesk.app` for the existing `scripts/install-local.sh`.
It never installs or launches the app. `LocalDelivery.xcconfig` is applied only
through the build process's `XCODE_XCCONFIG_FILE`; custom Runner variables select
the original `SeekDesk` product and `com.seekdesk.client` identifier without
renaming Flutter frameworks or changing the default preview configuration.

The original Cobalt `.icns` is copied as `SeekDesk.icns`; the unused template icon
is not selected by the asset compiler. Version and build numbers must match the
root `VERSION` and `BUILD_NUMBER`. The current source `Distribution/Info.plist`
defines no custom URL schemes or Sparkle feed/public key, so this local build
does not invent any. The production identifier permits the existing `Updates`
service, which remains disabled when its validated feed configuration is absent;
preview identities never initialize it.

Verify the prepared package before normally quitting SeekDesk. After confirming
exit, export a fresh private preference backup, run the repository installer,
then launch the exact `/Applications/SeekDesk.app` path. Verify the installed
inventory, signature, single running process and retained state. Do not import
an older snapshot to undo user changes. Local ad-hoc signature verification is
not Apple Developer ID signing or notarization, and this workflow performs no
GitHub upload or release.

Connected-client acceptance must obey the user's read-only testing boundary.
Use injected local services for automated publishing, messaging, upload,
credential-mutation and account-state cases; do not submit those operations to
the live forum. Recorded engine timings and simulated pointer input do not
establish presented FPS or physical-device handfeel.
